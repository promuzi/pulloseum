2026-10-16 사용자 "ㅇㅇ 올려"로 처음 올림 → **https://pulloseum.getchat.workers.dev** (이 PC를 꺼도 늘 같은 주소). 메카(`C:\dev\mecha-haran\proto\net\cf`)와 같은 방식·같은 계정.

## 무엇이 어디에 올라가나

| 무엇 | 내용 |
|---|---|
| 주소 | `https://pulloseum.getchat.workers.dev` (`/` → `/v2/`) |
| 앞단(Worker) | `cf/src/worker.js` — 게임 화면 파일은 Cloudflare 정적 파일이 바로 내주고 `/api/*`만 본체로 넘김 |
| 본체(Durable Object `Hub` 하나) | 서버 코드 `server/api.mjs` · `game.mjs` · `rooms.mjs` · `log.mjs` · `auth.mjs` + 규칙 `v2/src/game/` — PC 서버와 같은 코드 |
| 저장소 | `Hub`의 SQLite(표 = `server/schema.mjs`) — 계정(비밀번호는 scrypt 해시만) · 로그인 열쇠 해시 · 게임 저장 · 봇 판 · 플레이 기록. **PC 서버(`server/data/pulloseum.db`)와 따로** |
| 정적 파일 | `node cf/build.mjs`가 `cf/public/`(깃 밖)에 모은 게임 화면 파일 232개(7MB 남짓) — 서버 코드·저장소·문서는 안 올라감 |
| 계정 | homocarbo · 메카를 올린 그 Cloudflare 계정(무료 요금제), 이 PC의 로그인(OAuth) |

- ⚠ **workers.dev 하위 주소(`getchat`)는 바꾸지 않는다** — 바꾸면 갯챗이 깨진다. `wrangler subdomain` 명령을 쓰지 않는다.
- 무료 요금제: 앞단 하루 10만 요청(친구 대결 기다리는 요청 = 25초에 한 번), 본체 요청당 계산 30초, SQLite 5GB. 넘으면 요금이 아니라 오류.
- 친구 대결 방은 본체 메모리에 있음 — 아무도 없으면 본체가 잠들며 사라짐(PC 서버와 같음). 계정·저장은 SQLite라 남음.

## 올리기(코드나 그림을 바꾼 뒤)
PowerShell(이 기기 환경변수 `CLOUDFLARE_API_TOKEN`은 다른 프로젝트용 — 이 창에서만 지움):
```
cd C:\dev\pulloseum
node cf/build.mjs
cd cf
Remove-Item Env:CLOUDFLARE_API_TOKEN -ErrorAction SilentlyContinue
node C:\dev\homocarbo\node_modules\wrangler\bin\wrangler.js deploy
```
확인: `node cf/pagecheck.mjs https://pulloseum.getchat.workers.dev`(게임 화면이 뜨고 빠진 파일·오류 없는지 — 원래 없는 게일바인 어린 단계 그림·favicon은 넘어감).
- ⚠ **올린 뒤 본체(`Hub`)가 새 서버 코드로 바뀌기까지 4~5분 걸림**(2026-10-16 두 번 실측 — 그동안 `/api/*`는 옛 코드로 답함, 화면 파일은 바로 바뀜). 서버 코드를 고쳤으면 바뀐 답이 나오는지 보고 나서 시험한다(새 주소가 404여도 바로 고장으로 보지 않기).

## 플레이 기록 보고서(올린 서버)
```
node server/report.mjs --url https://pulloseum.getchat.workers.dev --days 30
```
- 본체의 `GET /api/admin/export`(관리 열쇠가 맞을 때만, 아니면 없는 주소 404)에서 계정 번호·만든 때·마지막 접속 · 플레이 기록 · 세이브를 받아 PC 판과 같은 보고서를 만든다(아이디·비밀번호·IP는 안 나감).
- 관리 열쇠 = Worker 비밀값 `ADMIN_KEY`, 이 PC의 사본 = `cf/.admin-key`(깃 밖 · 채팅·문서에 적지 않기). 다른 기기에서 보려면 열쇠를 새로 만들어 넣는다: 새 32자 문자열을 `cf/.admin-key`에 쓰고 cf 폴더에서(토큰 환경변수 지운 창) `Get-Content .admin-key | node C:\dev\homocarbo\node_modules\wrangler\bin\wrangler.js secret put ADMIN_KEY`.
- PC 서버에서도 같은 주소를 쓰려면 환경변수 `PULLO_ADMIN_KEY`(없으면 그 주소 자체가 없음).

## 구글 로그인 켜기
서버에 구글 클라이언트 ID가 없으면 처음 화면에 '구글로 계속하기' 단추가 안 보인다(아이디 · 비밀번호 로그인은 그대로).
1. https://console.cloud.google.com 에서 프로젝트를 하나 만들고 **Google 인증 플랫폼(OAuth 동의 화면)** 을 설정: 앱 이름 '풀로세움' · 지원 이메일 · 대상 '외부'. 쓰는 범위는 이름(openid · profile)뿐이라 심사가 필요 없다. '테스트' 상태로 두면 테스트 사용자로 적은 구글 계정만 들어오므로, 친구들이 쓰게 하려면 **'앱 게시'(프로덕션)** 를 누른다.
2. **클라이언트 → 클라이언트 만들기 → 웹 애플리케이션** · 승인된 자바스크립트 원본 = `https://pulloseum.getchat.workers.dev`, `http://localhost:8790`(PC 서버), `http://localhost:8788`(미리보기 시험 서버). 리디렉션 URI는 비워 둔다(팝업 방식).
3. 나온 **클라이언트 ID**(`…apps.googleusercontent.com`)만 쓴다 — 클라이언트 보안 비밀번호(secret)는 필요 없고 어디에도 적지 않는다. 클라이언트 ID는 화면에도 그대로 보이는 공개값이라 깃에 들어가도 된다.
4. Cloudflare: `cf/wrangler.jsonc`에 `"vars": { "GOOGLE_CLIENT_ID": "<클라이언트 ID>" }`를 넣고 위 '올리기'대로 다시 올린다(본체가 새 값을 읽기까지 4~5분). PC 서버: 환경변수 `PULLO_GOOGLE_CLIENT_ID`.
- 계정은 `g:<구글 번호>`로 저장(비밀번호 없음 · `provider = google`), 화면에는 '구글 계정'으로만 보임. 서버는 받은 접근 토큰을 구글에 물어 받는 쪽이 우리 클라이언트 ID인지 확인한다(`server/api.mjs googleWho`).
- ⚠ 안드로이드 앱(웹뷰)에서는 구글이 이 팝업 로그인을 막는다 — 앱판은 네이티브 구글 로그인 플러그인이 따로 필요(`docs/android-capacitor-wrapper.md`).
