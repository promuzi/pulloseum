# 전투 시뮬레이션 자동 시험 — 조사와 설계안 (2026-10-21)

> 사용자 요청(2026-10-21 밤): "전투 시뮬레이션도 고민해줘. 특정 조합과 경우의 수 등을 최적으로 돌려서 큰 오류를 잡아낼 수 있도록. 무조건 이기거나 밸런스가 무너지거나 이런 것 등 잡아내고, 특정 경우에 버그 발생하거나 등. 모든 경우의 수는 할 수 없으니 최적의 방안을 조사 분석해줘. 소스나 이런 것도 찾아보면 좋고. 이것으로 일일이 AI 쓰지 않고 적절히 테스트할 수 있게. 그것도 빠르게."
>
> **상태:** 조사·설계만 했다. 게임 코드와 기존 시험은 바꾸지 않았고, 어떤 단계부터 만들지는 사용자가 고른다. 시험은 모두 코드로 돌며 AI(언어 모델)를 쓰지 않는다.

## 1. 지금 있는 것과 실측

**전투 엔진**은 이미 시험하기 좋은 모양이다. 같은 씨앗(난수 시작값)과 같은 선택이면 결과가 똑같이 나오고(`v2/src/battle/rules.js makeRng`), 계산은 화면과 떨어진 순수 함수다. 1:1은 `makeBattle`·`playTurnVs`, 3:3은 `makeTeamBattle`·`playTurn3`, 봇 머리는 `aiPick`(공격력·새 효과·상황에 따라 가중치를 준 무작위 선택)이다.

**기존 시험 도구**(`tools/test/`):

| 파일 | 하는 일 | 한계 |
|---|---|---|
| `specbalance.mjs` | 종 리그전 — 1:1로 모든 종을 서로 붙여 평균 승률 | 짝마다 16판(오차가 큼), 양쪽 모두 같은 봇 |
| `cardbalance.mjs` | 같은 식물에 카드만 다르게 끼워 승률 비교 | 카드 하나씩만 봄 |
| `botbalance.mjs` | 내 식물 대 봇 공정성 | — |
| `matchup`·`status`·`devices`·`edgecases`·`team3v3`·`rules.test` | 손으로 쓴 규칙 시험 | 생각한 경우만 잡음 |

**실측**(이 PC · 한 코어 · Node 24, 측정 스크립트 [`bench.mjs`](../../../tools/design/battle-sim-20261021/bench.mjs) · 결과 [`bench-result.json`](../../../tools/design/battle-sim-20261021/bench-result.json)):

| 항목 | 결과 |
|---|---|
| 1:1 무작위 대전 | 초당 약 **5,900판**(한 판 0.17ms, 평균 10.8턴) |
| 3:3 무작위 대전 | 초당 약 **1,200판**(한 판 0.8ms, 평균 36턴) |
| 무작위 2,500판의 오류 | 예외 0 · 체력/햇빛 범위 벗어남 0 · 80턴 무승부 0 |
| 전투 상태 복사(JSON 왕복) | 약 **17µs**, 상태 크기 약 2KB |

이 PC는 6코어 12스레드라 병렬로 돌리면 6~10배 빨라진다. 45종 1:1 리그(990짝)를 짝마다 200판 두어도 한 코어로 약 34초다.

**지금 방식의 빈틈**

1. 양쪽이 같은 봇이라 '잘 두는 사람이 찾는 사기 조합'을 못 찾는다. 봇끼리 50%여도 사람이 두면 한쪽이 무조건 이길 수 있다.
2. 짝마다 16판이면 승률 오차가 ±12%p쯤이다(95% 범위로는 ±25%p). 쏠림을 판정하기엔 너무 적다.
3. 3:3 팀(45종에서 셋 = 14,190팀), 기술 여섯·카드·변이 조합은 다 돌릴 수 없다.
4. 규칙 버그는 손으로 쓴 경우만 잡는다. 여러 효과가 겹치는 경우가 비어 있다.
5. 결과를 저장해 '규칙을 바꾼 뒤 무엇이 달라졌는지' 비교하는 기준표가 없다.

## 2. 조사한 방법

| 방법 | 핵심 | 우리에게 쓰는 곳 |
|---|---|---|
| 포켓몬 쇼다운 시험 도구 | 무작위 대전을 반복해 오류를 찾고, exhaustive 모드는 **아직 안 써 본 기술·특성·도구부터 고르는 봇**으로 한 바퀴에 모든 선택지를 한 번씩 쓴다. 실패하면 씨앗과 재현 명령을 출력한다. dual 모드는 매 입력 뒤 전투 상태를 JSON으로 저장했다 다시 불러와 원본과 같은지 비교한다 | 버그 찾기(단계 1)의 뼈대. 방 저장·서버 재시작 안전 확인 |
| 제한 플레이(restricted play) | 한쪽 봇에 '이 기술 금지' 같은 제한을 걸고 보통 봇과 붙여, 그 요소가 승률에 주는 힘을 잰다 | 기술·효과 하나의 힘 측정, 쓸모없는 기술 찾기 |
| 진화 탐색으로 덱 찾기 | 진화 알고리즘이 덱을 만들고, 사람이 덱을 고치는 방식의 돌연변이로 탐색을 줄여 사람이 만든 덱보다 센 덱을 찾았다 | 사기 조합 찾기(단계 4) |
| MAP-Elites(품질·다양성 탐색) | 전략 성향 칸마다 최강 조합을 따로 남겨 한 가지 해법에만 몰리지 않는다 | 공격형·수비형·상태형마다 최강 조합 찾기 |
| 메타 진화(밸런스 수정 탐색) | 카드 수치 변경 조합을 탐색해 대결 승률을 50% 쪽으로, 변경은 최소로 | 나중에 밸런스 수치 후보 찾기 |
| 성향 봇(procedural personas) | 성향이 다른 탐색 봇들을 시험꾼 대신 쓴다 | 공격형·수비형·상태형 봇 |
| Nash 평균 | 비슷한 약한 상대가 많아 평균 승률이 부풀려지는 것을 막는 평가 | 종 점수 매기기 |
| SPRT(순차 판정, 스톡피시 Fishtest) | 판 수를 미리 정하지 않고, 차이가 확실해지면 그 자리에서 멈춘다 | 리그 판 수 절약 |
| 반씩 거르기(successive halving) | 후보를 반씩 탈락시키고 남은 후보에 판을 몰아준다 | 3:3 강팀 후보 좁히기 |
| 같은 씨앗 짝(common random numbers) | 비교하는 두 경우에 같은 난수를 같은 용도로 써서 운 차이를 지운다. 같은 정확도에 필요한 실행을 10배 넘게 줄인 사례가 있다. 난수 쓰는 순서가 어긋나면 효과가 줄어든다 | 카드·규칙 A/B 비교 |
| 조합 시험(커버링 배열, NIST) | 오류 대부분은 요소 2~3개의 조합에서 난다. 모든 2~3개 조합이 한 번씩 나오는 표로 시험 수를 크게 줄인다 | 효과 겹침 장면 만들기(단계 2) |
| 성질 기반 시험(fast-check) | 무작위 입력으로 '항상 참이어야 할 성질'을 검사하고, 실패하면 가장 짧은 재현 사례로 줄여 주며 씨앗으로 다시 돌린다 | 버그 찾기(단계 1)의 실패 사례 줄이기 |

## 3. 풀로세움 시험 설계 — 네 단계

### 단계 1. 버그 찾기 — 무작위 대전 + 불변식 (빠른 모드 1분)

매 턴 끝에 아래 성질을 검사한다. 하나라도 어기면 그 판의 씨앗·팀·선택 기록을 저장한다.

- 체력 0~최대, 햇빛 0~8(3:3은 팀 공용), 숫자 아닌 값(NaN) 없음, 예외 없음
- 상태 이름이 정해진 목록에 있고, 남은 턴·겹이 음수이거나 끝없이 늘지 않음
- 판이 80턴 안에 끝남. 체력이 K턴 동안 그대로면 '끝없는 반복'으로 표시
- 같은 씨앗·같은 선택이면 같은 결과(결정론)
- 매 턴 상태를 JSON으로 저장했다 다시 불러와 이어 둔 결과 = 그냥 둔 결과(쇼다운 dual 방식, 방 저장 안전)
- 확정 규칙 위반 감시(규칙을 게임에 적용한 뒤): 도발 중 공격이 아닌 기술 사용, 면역 중 기절, 제한 상태가 다음 1턴을 넘김 등

**입력 고르기:** 쇼다운 exhaustive처럼 '아직 안 써 본 기술·안 걸린 상태·안 쓴 카드와 변이부터' 고르는 봇을 둔다. 한 바퀴를 돌면 모든 기술이 한 번 이상 쓰이고 모든 상태가 한 번 이상 걸린다. 바퀴 수와 실패 수 상한을 둔다.

**실패 사례 줄이기:** 저장한 선택 목록에서 하나씩 빼 보며 여전히 실패하는 가장 짧은 경우를 남긴다(fast-check의 줄이기와 같은 생각). 결과는 '씨앗 + 식물 + 선택 몇 개'라 바로 고칠 수 있다.

**비용:** 1:1이 초당 약 6천판이라 1분에 30만판 이상 돌릴 수 있다. 매 턴 JSON 왕복 검사를 켜면 2~3배 느려지므로 일부 판에만 켠다.

### 단계 2. 규칙 표 시험 — 엑셀 확정 규칙을 장면으로 (수 초)

- 엑셀 v8의 확정 규칙마다 '이렇게 걸면 → 이렇게 돼야 함' 장면을 하나씩 만든다. 예: 봉인은 다음 1턴이고 기절로 쉬어도 끝남, 면역은 다음 행동 한 번 뒤 끝남, 보호막은 연타 전체를 남은 양까지 흡수, 조준은 모든 타에 적용, 암실은 지금 N턴.
- 규칙을 게임에 '적용해' 할 때 이 표가 그대로 합격 기준이 된다. 엑셀과 코드가 어긋나면 바로 드러난다.
- **효과 겹침:** 상태·기술 태그를 요소로 놓고, 모든 2~3개 조합이 한 번씩 나오는 커버링 표로 장면을 만든다(예: 연타 × 보호막 × 반사, 도발 × 봉인 × 햇빛 부족, 기절 × 면역 × 빙결). 모든 조합보다 훨씬 적은 장면으로 대부분의 겹침 오류를 잡는다.

### 단계 3. 밸런스 리그 — 쏠림 찾기 (1~5분)

**1:1 종 리그:** 45종, 990짝.
- 짝마다 판 수를 정하지 않고 순차 판정(SPRT)으로 둔다. 50%에서 크게 벗어난 짝은 일찍 멈추고, 애매한 짝만 더 둔다.
- 같은 씨앗으로 자리를 바꿔 두 번씩 두어 운과 선공 차이를 지운다.

**보고할 경고:**
- 평균 승률 60% 넘음 / 40% 밑
- 모든 상대에게 55% 넘음 = '무조건 이김' 후보
- 특정 짝 80% 넘음 = 상성이 너무 셈
- 선공 쪽 승률 차이, 80턴 무승부 비율, 평균 턴이 너무 짧거나 김
- 거의 안 쓰이는 기술, 거의 안 걸리는 상태(사용 통계)

**봇을 여러 종류로 둔다.** 같은 봇끼리 50%여도 수읽기 봇에서 한쪽이 크게 이기면 '잘 두면 사기'라는 뜻이다.

| 봇 | 내용 | 속도(추정) |
|---|---|---|
| 무작위 | 바닥 기준 | 가장 빠름 |
| 지금 봇(`aiPick`) | 보통 실력 | 초당 약 6천판 |
| 수읽기 봇 | 내 후보 × 상대 후보를 실제로 한 턴씩 계산해 고름(상태 복사 17µs라 가능) | 한 코어 초당 수십 판 |
| 성향 봇 | 공격형·수비형·상태 위주 | 지금 봇과 비슷 |
| 제한 봇 | 특정 기술·효과 금지 → 그 요소의 힘을 잼 | 지금 봇과 비슷 |

**3:3:** 팀 조합이 너무 많으므로 아래 세 가지로 좁힌다.
- 무작위 팀 표본을 둔다.
- 종 하나가 들어간 팀과 빠진 팀의 승률 차를 잰다.
- 반씩 거르기로 강팀 후보에만 판을 더 준다.

### 단계 4. 사기 조합 탐색 — 최악의 경우 찾기 (밤샘용)

- **진화 탐색:** 후보 하나 = (종, 기술 여섯, 카드 둘, 변이) 또는 3:3 팀이다. 점수는 대표 상대 묶음에 대한 수읽기 봇 승률이다. 돌연변이는 사람이 덱을 고치듯 기술 하나·카드 하나를 바꾼다. 75%를 넘는 조합이 나오면 '사기 후보'로 보고한다.
- **MAP-Elites:** 공격형·수비형·상태형 칸마다 최강 조합을 따로 남겨, 한 가지 전략만 찾고 끝나는 것을 막는다.
- **무조건 이기는 수순 찾기:** 상대를 고정 봇으로 두고, 정해진 몇 수의 선택 열(빔 탐색)로 항상 이기는지 본다. 기절이 끝없이 이어지거나, 회복이 끝없거나, 햇빛을 계속 말리는 '고리'를 찾는다.
- **사용자 요청 확인 항목(2026-10-21):** 게일바인이 횟수 제한 없는 은신 ‘그건 내 잔상인데?’만 반복해서 이길 수 있는지 확인한다(사용자 ‘일단 나중에 은신만 써서 이길 수 있는지 확인해줘. 그러면 밸런스 수정을 좀 해야하니깐’). 광역·연타를 든 상대와 안 든 상대를 나눠 보고, 이기면 밸런스를 고친다([종 기술 표 11번](2026-10-18-v2-species-skills.md)). 같은 때 ‘이딴게.. 공격?’(도발 + 교란) 다음 턴에 은신·방심하기로 잇는 조합과, ‘피해?’(늘 반드시 맞음·자세 무시·선공이면 확정 치명)의 세기도 함께 본다.

## 4. 빠르게 돌리는 요령

- **병렬:** Node `worker_threads`로 코어 수만큼 나눠 6~10배.
- **판 수 절약:** 순차 판정과 반씩 거르기.
- **운 지우기:** 같은 씨앗 짝과 자리 바꾸기. 행동마다 난수 줄기를 나누면 비교가 더 정확해진다.
- **재사용:** 식물·기술표를 미리 만들어 둔다(지금 `plantOf`도 그렇게 함).
- **회귀 비교:** 결과를 JSON 기준표로 저장하고, 규칙을 바꾼 뒤 이전과 달라진 곳만 표시한다.
- **두 가지 모드:** 빠른 모드(약 1분: 단계 1 1만 판 + 단계 2 + 1:1 리그 짝마다 최대 100판)와 깊은 모드(밤샘: 3:3·수읽기 봇·진화 탐색).

## 5. 엔진에 필요한 작은 준비

- **난수 상태 저장:** 지금 `makeRng`는 상태를 함수 안에 숨긴다. 상태를 꺼내고 넣을 수 있게 하면 수읽기 봇·장면 재현·같은 씨앗 비교가 정확해진다(전투 계산 결과는 그대로).
- **행동별 난수 줄기:** 선공 판정·명중·치명·상태 확률을 각자 다른 줄기로 뽑으면, 한쪽만 바꾼 비교에서도 나머지 운이 그대로 맞는다.
- **시험용 기록:** 매 턴 `events`에 이미 사건이 남으므로 사용 통계와 불변식 검사에 그대로 쓴다.
- **선택:** `package.json`에 `"type": "module"`을 넣으면 실행할 때마다 나오는 모듈 형식 경고가 사라진다.

## 6. 제안 구현 순서 (사용자 선택 대기)

| 순서 | 만들 것 | 걸리는 시간(돌리기) | 작업량 |
|---|---|---|---|
| 1 | `tools/sim/fuzz.mjs` — 단계 1(커버리지 봇 + 불변식 + JSON 왕복 + 실패 줄이기) | 빠른 모드 약 1분 | 반나절 |
| 2 | `tools/sim/rules-table.mjs` — 단계 2(엑셀 확정 규칙 장면 + 겹침 커버링 표) | 수 초 | 규칙을 '적용해' 할 때 같이 |
| 3 | 리그 개선 — 단계 3(`specbalance` 기반 순차 판정·병렬·여러 봇·보고서·기준표) | 1~5분 | 하루 |
| 4 | `tools/sim/search.mjs` — 단계 4(진화 탐색·MAP-Elites·수순 찾기) | 밤샘 | 하루~이틀 |

1번은 지금 게임에도 바로 쓸 수 있다. 2번은 효과 규칙을 코드에 적용하는 작업과 함께 만드는 것이 맞다. 3·4번은 종 리그전(밸런스) 단계에서 쓴다.

**외부 소스 활용:** 포켓몬 쇼다운(MIT 허가)은 코드를 가져오지 않고 구조만 참고한다. fast-check(MIT 허가)는 개발용 의존성으로 넣을 수 있다. 커버링 표는 작은 생성기를 직접 쓰거나 미리 만든 표를 쓴다.
